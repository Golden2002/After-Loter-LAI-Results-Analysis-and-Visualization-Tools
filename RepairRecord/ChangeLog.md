## 一、核心问题修复

### 1.1 跨染色体片段处理负值问题
- **问题描述**: 原始版本中跨染色体片段导致 MIN_LENGTH_BP 计算为负值
- **修改文件**: `loter_segment_analyzer.py`
- **修改模块**: `LoterSegmentAnalyzer.extract_segments_with_positions()`
- **修改位置**: 第 150-190 行

**原代码 (v2.0.0)**:
```python
# 找到祖源变化的位置
change_points = np.where(hap[:-1] != hap[1:])[0] + 1
start_idx = 0
```

**新代码 (v2.1.0)**:
```python
# 找到祖源变化的位置（祖源变化 或 染色体边界）
change_points = []

for i in range(n_snps - 1):
    # 祖源发生变化
    if hap[i] != hap[i + 1]:
        change_points.append(i + 1)
        continue

    # 物理位置回退（新染色体）
    pos_i = self.snp_map.loc[i, 'POS']
    pos_j = self.snp_map.loc[i + 1, 'POS']
    chr_i = self.snp_map.loc[i, 'CHR']
    chr_j = self.snp_map.loc[i + 1, 'CHR']

    if (chr_i != chr_j) or (pos_j < pos_i):
        change_points.append(i + 1)

change_points = np.array(change_points)
start_idx = 0
```

**修复原理**:
- 在原仅检测"祖源变化"的基础上，增加"染色体变化"和"位置回退"检测
- 当检测到新染色体或物理位置减少时，强制划分新片段
- 确保每个片段都在同一染色体上，避免跨染色体负长度计算

### 1.2 移除冗余的跨染色体处理函数
- **修改模块**: 删除了 `handle_cross_chromosome_segments()` 方法的调用
- **原因**: 由于在源头已正确处理跨染色体，无需后续补救处理

## 二、性能优化

### 2.1 数据结构优化
- **新增模块**: `_preprocess_snp_arrays()` 方法
- **新增字段**: 
  - `chr_array`: NumPy 数组存储染色体信息
  - `pos_array`: NumPy 数组存储位置信息
  - `chr_boundaries`: 预计算的染色体边界索引

**优化效果**:
- 将 DataFrame 的列转换为 NumPy 数组，提升访问速度 10-100 倍
- 避免重复的 `DataFrame.loc` 操作

### 2.2 向量化操作优化
- **修改模块**: `extract_segments_with_positions()` 方法的边界检测逻辑
- **优化技术**:
  - 使用 `np.where()` 替代 Python 循环
  - 预计算染色体变化掩码 `chr_change_mask`
  - 预计算位置回退掩码 `pos_decrease_mask`

### 2.3 内存优化
- **修改模块**: `load_loter_result()` 方法
- **新增功能**:
  - 使用 `mmap_mode='r'` 加载大文件，减少内存占用
  - 自动检测内存布局，选择最佳加载策略
